            exec.console capability, v1, stable

            A console (UART, emulator serial port) whose output is recorded from the moment it opens.

            suggested role: console

            Members

            • open() -> None (required): Opens the console and starts recording; normally done by the state, not by tests.
            • is_open() -> bool (required): True while the console is open and its reader is healthy.
            • close() -> None (required): Stops recording and releases the device; called at teardown.
            • write(text: str) -> None (required): Sends one line of text (a newline is appended). Raises RuntimeError when not open.
            • mark() -> int (required): A cursor for lines() and wait_for(); only lines received after this call count.
            • lines(since: int = 0) -> list[str] (required): The recorded lines, from the cursor `since` (default: everything still buffered).
            • wait_for(pattern: str, timeout: float = 30.0, *, since: int | None = None, regex: bool = False) -> str | None (required): The first line containing (or matching) the pattern after `since` (default now), or None on timeout.

            Guarantees

            • Output printed since the console opened is recorded, not only output after the first read.
            • lines(since=mark) returns only lines received after the mark was taken.
            • run reports the exit code of the command.

                          core_dump 0.1.0

                          Copies core files off every scope that has `exec.command` and `files.transfer`, at teardown. It declares no capabilities or actions, so it has no labels; enable it with its Bazel flag.

                          Factories: -

                          Actions: -

                          Prerequisites

                          • enable with --//score/itf/packs/core_dump:extract_core_dumps
                          • output in $TEST_UNDECLARED_OUTPUTS_DIR/coredumps or --//score/itf/packs/core_dump:core_dumps_output_dir

                          dlt 0.1.0

                          DLT logs over a TCP stream, UDP multicast or the bundled dlt-receive. Every variant has its own action making `logs.active` true: name one with `by:` in a goal.

                          Factories: dlt.multicast, dlt.receive, dlt.receive_tcp, dlt.stream

                          Actions: dlt.join, dlt.start_receive, dlt.subscribe

                          Prerequisites

                          • none beyond the build (dlt-receive and libdlt are built from source)
                          • the patched DLT build listens on TCP 13490

                          docker 0.1.0

                          A container as the target platform, reached through the Docker API (works with any image) and, with the ssh pack, over SSH.

                          Factories: docker.endpoint, docker.exec, docker.files, docker.platform, docker.process

                          Actions: docker.start

                          Prerequisites

                          • a Docker-compatible daemon (DOCKER_HOST for Podman)
                          • under rootless Podman, publish ports and use docker.endpoint with via=published

                          local 0.1.0

                          The test host as the platform: commands, processes and files through subprocess.

                          Factories: local.exec, local.files, local.platform, local.process

                          Actions: local.start

                          Prerequisites

                          • none

                          Actions: pcap.start, pcap.start_on_host
